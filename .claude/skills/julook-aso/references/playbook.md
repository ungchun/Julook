# ASO Playbook (검증된 규칙 + 의사결정 룰)

> 상위 SKILL.md의 보조 문서. 키워드 100자 슬롯 우선순위와 데이터 해석 룰.

---

## 1. 슬롯 우선순위 (위에서 아래로 채움)

키워드 100자 한도 안에서 다음 순서대로 자리 배정.

| 순위 | 슬롯 카테고리 | 설명 | 예시 |
|------|---------------|------|------|
| 1 | **밥줄 키워드** | 실측 다운로드 일으키는 키워드 (Top downloads 5%+) | 키햐 |
| 2 | **경쟁 주류 앱 차용** | Top 5 경쟁사 브랜드명 (한글 + 필요 시 영문) | 데일리샷, 술담화, 비비노, vivino, 달리, 요즘이술 |
| 3 | **주종 long-tail** | 앱 이름에 없는 주종 카테고리 | 위스키, 와인, 사케, 하이볼, 탁주, 약주, 청주 |
| 4 | **소비 상황** | MZ 트렌드 검색 (홈술/혼술 등) | 홈술, 혼술, 안주, 홈파티 |
| 5 | **추천형 long-tail** | 검색량 있는 의도 키워드 | 추천, 술추천, 막걸리종류 |
| 6 | **기능/문맥** | 앱 기능과 검색 의도 매칭 | 양조장, 페어링, 시음회, 노트 |

**규칙**: 위 순서를 지키되 100자 한계 도달 시 6→5→4→3 순으로 가지치기. 1, 2번은 사수.

---

## 2. 슬롯 자동 제외 룰

다음 단어는 **자동 제외** (포함하면 슬롯 낭비):

1. **앱 이름·부제목에 이미 들어간 단어** — Apple이 단일 인덱스로 합치므로 중복 의미 없음
2. **노출 0 + 다운로드 0이 4주 이상 지속된 단어** — 이미 안 잡히는 단어
3. **막걸리 카테고리와 무관한 일반 앱 이름** — 다이소/이마트24/gs25/캐치테이블/테이블링/11번가/두잇/땡겨요/쿠팡이츠/무신사/29cm/패스오더/app 등 (실측 0%로 검증됨)
4. **단일 영문 의미 없는 단어** — `app`, `the`, `service` 등

---

## 3. 한글/영문 슬롯 판단 룰

| 상황 | 결정 |
|------|------|
| 앱 이름이 한글, 사용자도 한국 → 한글이 1순위 | 한글 우선 배치 |
| 영문 브랜드명이 한국에서도 영문으로 검색됨 (Vivino, Apple Music 등) | **한글+영문 둘 다** 슬롯 차지 |
| 영문 브랜드명이 한국에서 한글로만 검색됨 | 한글만 |
| 영문 단어 슬롯 비용이 너무 큼 (6자 이상) + 한글 검색이 압도적 | 영문 제거하고 long-tail 추가 |

> **Vivino 케이스**: 한국어 미지원 앱이지만 와인 좋아하는 사용자는 영문으로도 검색. 6자 비용 감수하고 둘 다 둠. (다만 다음 사이클에서 비비노 단독으로도 무방)

## 4. 데이터 해석 룰

### Top impressions (노출 점유율)
- 단일 키워드 70%+ → **위험 신호**. 그 키워드 하나 빠지면 노출 폭락. 반드시 다양화.
- Top 10 키워드 합 90% 미만 → 분산 잘 됨.

### Top downloads (다운로드 점유율)
- 5% 이상 = 효자 (절대 제거 금지)
- 1~5% = 보조 (유지)
- 1% 미만 + 노출 1% 미만 4주 지속 = 제거 후보

### Missing keywords
- **카테고리 일치 + 검색량 큼** → 추가 후보
- **카테고리 무관 + 단순 인기 앱** → 추가해도 잡힐 가능성 낮음 + 잡혀도 전환 0
- 이미 키워드 필드에 있는데 Missing에 뜨면 → **순위 자체가 낮음**. 메타데이터(앱 이름/부제목) 강화 필요.

---

## 5. 데이터가 부족할 때 (출시 초기 / Trial 만료 등)

### 우선순위
1. **App Store Connect → App Analytics → Sources → Search** (무료, 가장 정확)
2. **App Store에서 시드 키워드 직접 검색** → 자동완성 = 사람들이 실제 치는 검색어
3. **경쟁사 앱 페이지** 직접 방문 → 부제목/설명 텍스트 손으로 옮겨 기록
4. **AppFollow 무료 영역**: Top Charts, Featured Apps, Conversion Benchmark
5. **Mobile Action / Sensorier 무료 티어**

### 의사결정
- 경험적 추측만 있으면 **보수안** 채택 (검증 약한 키워드 줄이고 슬롯 일부 비움)
- 4주 후 다시 측정해서 가지치기

## 6. 변경 후 측정 사이클

```
Day 0   : 키워드 변경 적용 (Submit for Review)
Day 1~3 : 심사 통과 → 라이브
Day 7   : 첫 데이터 (아직 미성숙, 결정 X)
Day 14  : 1차 관찰 — 노출 변화 (다운로드는 아직 적을 수 있음)
Day 28  : 2차 관찰 — 다운로드 데이터 충분, 가지치기 결정
Day 28~ : 새 사이클 시작
```

**중요**: Day 7 이전에 키워드 빼지 말 것. 데이터 미성숙으로 잘못된 결정 위험.

---

## 7. 부제목 / 앱 이름 변경은 별도 사이클

키워드 필드 변경은 비교적 자유롭지만, **앱 이름·부제목 변경은 영향이 훨씬 큼**.

### 권장 순서
1. 키워드 필드로 새 키워드 효과 검증 (4주)
2. 효과 입증된 키워드 → 부제목으로 승격
3. 부제목 변경 후 4주 관찰
4. 핵심 키워드 → 앱 이름까지 승격 (마지막 단계)

### 주의
- 앱 이름 변경은 브랜드 인지도에 영향. 빈번한 변경 금지.
- 부제목 변경 시 이전 부제목에서 효과 보던 키워드가 빠지지 않게 주의.
