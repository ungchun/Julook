# 버그 수정

**버그는 증상. 근본은 대개 설계.** 그래서 red → refactor 흐름이 중요하다.

## 사이클 (변형)

1. **RED — 회귀 테스트**: 버그를 재현하는 실패 테스트를 먼저. 실제로 실패함을 확인.
2. **GREEN — 증상 제거**: 최소 수정으로 테스트 통과.
3. **REFACTOR — 근본 원인 완화**: 버그가 살아있던 주변의 설계/품질을 개선. 여기서 실제 재발 방지가 일어난다.
4. **GREEN — 전체 재검증**.

Phase 3(refactor)를 생략하면 같은 버그가 다른 경로로 재발한다.

## 왜 테스트부터인가

- 버그가 "재현 가능"하다는 증거가 생긴다.
- 고쳤다는 증거가 영구 보존된다 (회귀 방지).
- 테스트 없이 고치면 "고친 척" 하기 쉽다.

## 체크리스트

- [ ] 실패 테스트가 버그를 재현하는가? (테스트 코드만 봐도 버그가 뭔지 설명되는가)
- [ ] 수정 전 전체 테스트에서 **정확히 그 테스트만** 빨간가?
- [ ] 수정 후 전체 테스트가 녹색인가?
- [ ] 근본 원인을 찾아 주변을 정리했는가? ("수정 = 한 줄 변경"이면 대개 덜 본 것)
